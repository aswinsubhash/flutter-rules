R-01Critical

Result<T> cannot represent nullable or void success

Success is inferred from data != null. Therefore Result.success(null) and successful Result<void> are misclassified. fold() relies on data as T.

Risk
Broken state discrimination and runtime casts in core error flow.
Fix
Use an explicit success/failure discriminator or a sealed union. Add tests for nullable values and void success.
Source
architecture.md:50-85
R-02Critical

Validation ownership directly contradicts itself

One rule requires validation in Cubit/Bloc. Another requires presentation pages to isolate validation and complex business logic in private methods. Final pitfall rule again forbids validation in widgets.

Risk
Agents place business rules in both layers or move logic back and forth.
Fix
Pages collect input and dispatch actions. Cubit/domain owns business validation. Allow only presentation-only checks in widgets.

R-03Critical

Repository unit-test rule blocks repository testing

Repositories are listed as unit-test targets, but mocking below repository/service boundary is prohibited. Repository tests normally fake or mock datasources, clients, databases, or storage.

Risk

Fix
Mock external dependencies of the unit under test. For a repository test, its datasource/client is a valid boundary.
